Image Classification

problem: semantic gap 语义鸿沟

难以将计算机从图像中提取的特征与实际物体联系

challege

  1. viewpoint variation 观察角度导致图像不同
  2. intraclass variation 同类物体之间存在区别
  3. fine-grained categories 识别相近的不同类物体
  4. background clutter 背景混乱干扰
  5. illumination changes 照明干扰
  6. deformation 物体变形
  7. occlusion 遮挡

Image Classification Datasets 常见数据集

  • MNIST
  • CIFAR10
  • CIFAR100
  • ImageNet
  • MIT Places
  • Omniglot

K最邻近算法

训练时记录所有训练数据为样本点，测试时计算测试数据与样本点之间的距离，根据最近的K个样本点给出输出label

复杂度：

  1. 训练时：O(1)。训练时只需构建指向训练数据的指针
  2. 测试时：O(N)。需要遍历训练数据，与测试点比较

优化：K等于n>1

  • 边界更平滑
  • 减少噪音影响
  • 可能使得一些区域无法判断属于什么label

hyperparameter 超参数的选择：

超参数包括 distance metric 和 K

两种dm：

  • d1(I1,I2) = ∑p|I1p−I2p|
  • $d_2(I_1, I_2) = \sqrt{\sum_p(I_1^p - I_2^p)^2}$​

超参数一般不能从训练中获得，需要手动设置：

  1. 选择在整个数据集上表现最好的K——Bad 因为K=1时算法永远在数据集上永远正确率100%

  2. 数据集分为train 和 test，选择在test上表现最好的K—— Bad 因为只针对test优化，不清楚算法在新数据上效果如何

  3. 数据集分为train validation 和 test，选择在val上表现最好的K，并只在test上测试一次来检验算法性能——better 优化算法的同时能从test上得到比较客观的算法性能评估。（但是实践中如果test准确率很低，只能恭喜你白干了）

  4. Cross-Validation 将数据分成n份folds和1份test。依次将fold作为validation，然后结果取平均——对小数据集很有用，但是很耗算力，总的来说不常用

K最邻近算法的应用：

少用于原始像素计算：

  1. 维度灾难。在相同覆盖密度之下，针对高维数据的训练所需要的数据呈指数级增长
  2. test速度非常慢，O(N)级别。
  3. 像素间的距离没有什么实际语义（几个人类看起来差别不大的图片，算法可能认为距离很不同）

使用特征向量进行距离计算，效果很好。
